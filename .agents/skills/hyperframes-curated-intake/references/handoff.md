# Handoff prompt

`HANDOFF.md` is the human execution controller for the later `$hyperframes` run. It contains:

- approved delivery and timing summary;
- canonical artifact map;
- complete scene/path/contract table;
- unresolved catalog or asset items;
- state model and build protocol;
- one copy-ready prompt.

The copy-ready prompt directs HyperFrames to:

1. read `BRIEF.md`, `frame.md`, `STORYBOARD.md`, the handoff manifest, curation, Build Plan, media manifest, and every scene contract;
2. run handoff preflight before authoring;
3. begin at Sketch with the approved scene concepts and preserve each scene's teaching classification and narrative scale;
4. finalize exact selections in the Build Plan;
5. stage and inspect selected implementations;
6. integrate Blocks and Components through their documented mechanisms;
7. install and integrate the real transition implementation at every declared adjacent-scene boundary, preserving its same-background assessment, perceptual anchor, and color dependency;
8. bind scene and transition receipts to visible production elements;
9. verify against the manifest's complete expected scene set and `N−1` transition set;
10. capture the outgoing side, midpoint, and incoming side of every transition, then finish at Studio Preview and request render approval.

The handoff carries the files by path and hash. Source documents stay in their owning files, which keeps one authority for each decision.

In routed mode, also return `.hyperframes/curated-intake-result.json` with the original parent hash, exact cluster/segment scope, teaching scene contracts, beats, selected teaching Components, resolved questions, and any scope-change proposal. The result is input to Visual Director's bounded merge and must not edit the parent plan itself.
